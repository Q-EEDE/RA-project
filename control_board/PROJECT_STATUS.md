# 水果分类打包机项目状态记录

## 1. 项目名称

水果分类打包机

## 2. 当前总体目标

本项目基于瑞萨 RA6M5，实现水果自动输送、摄像头采集、分类判断、舵机分流、定量装盒和翻盖盒压盖等功能。

当前阶段优先完成硬件控制闭环，不追求复杂 AI 模型，先实现一套可以稳定演示的完整流程。

## 3. 当前阶段目标

- 推理板/摄像头板：完成 OV2640 图像采集流程。
- 控制板：完成电机、舵机、光电开关、包装流程的状态机控制。
- 后续：实现两块板之间串口通信，推理板发送分类结果，控制板执行分拣动作。

## 8. 推荐的软件结构

建议后续按功能模块拆分代码，先保持最小可运行版本，不要过早做复杂封装。

```text
src/
├── camera/
│   ├── camera.c
│   └── camera.h
├── motor/
│   ├── motor.c
│   └── motor.h
├── servo/
│   ├── servo.c
│   └── servo.h
├── sensor/
│   ├── sensor.c
│   └── sensor.h
├── state_machine/
│   ├── system_state.c
│   └── system_state.h
├── protocol/
│   ├── uart_protocol.c
│   └── uart_protocol.h
└── app/
    ├── app_main.c
    └── app_main.h
```

为什么这样划分：

- `camera/`：集中管理 OV2640、Arducam 和 FIFO 相关流程。
- `motor/`：集中管理输送带电机启停、方向和速度控制。
- `servo/`：集中管理分流挡板、压盖机构等舵机动作。
- `sensor/`：集中管理光电开关输入检测。
- `state_machine/`：集中管理整机运行流程，便于调试每个状态。
- `protocol/`：集中管理推理板和控制板之间的 UART 通信协议。
- `app/`：放主流程入口，把各模块连接起来。

## 9. 推荐状态机

| 状态 | 含义 |
| --- | --- |
| `SYSTEM_IDLE` | 系统空闲，等待启动 |
| `SYSTEM_FEEDING` | 输送带运行，水果进入检测区域 |
| `SYSTEM_WAIT_FRUIT` | 等待光电开关检测到水果 |
| `SYSTEM_CAPTURE_IMAGE` | 触发摄像头拍照并采集图像 |
| `SYSTEM_CLASSIFY` | 等待或执行水果分类判断 |
| `SYSTEM_SORTING` | 根据分类结果驱动舵机分流 |
| `SYSTEM_WAIT_BOX` | 等待包装盒到位或等待装盒条件满足 |
| `SYSTEM_PACKING` | 执行定量装盒流程 |
| `SYSTEM_CAPPING` | 执行翻盖盒压盖动作 |
| `SYSTEM_OUTPUT` | 输出完成后的水果盒 |
| `SYSTEM_ERROR` | 异常状态，停止执行并等待处理 |

建议的基本流程：

```text
SYSTEM_IDLE
    ↓
SYSTEM_FEEDING
    ↓
SYSTEM_WAIT_FRUIT
    ↓
SYSTEM_CAPTURE_IMAGE
    ↓
SYSTEM_CLASSIFY
    ↓
SYSTEM_SORTING
    ↓
SYSTEM_WAIT_BOX
    ↓
SYSTEM_PACKING
    ↓
SYSTEM_CAPPING
    ↓
SYSTEM_OUTPUT
    ↓
SYSTEM_FEEDING
```

如果出现摄像头通信失败、电机异常、传感器长时间无响应等情况，进入：

```text
SYSTEM_ERROR
```

## 11. 注意事项

- 不要同时给舵机和主控板直接共用不稳定电源。
- 舵机、电机、传感器和 RA6M5 必须共地。
- L298N 驱动电机时注意外部 12V 电源。
- 摄像头调试应先验证寄存器，再验证 FIFO，再验证完整图像。
- 当前阶段不要过早加入复杂 AI，先让系统流程跑通。
- 串口通信协议建议先设计简单格式，例如：分类编号、动作编号、校验位。
- 状态机调试时建议每进入一个状态都通过串口打印状态名，方便定位卡在哪一步。
