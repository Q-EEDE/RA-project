# 水果分类打包机项目状态记录

## 1. 项目名称

水果分类打包机

## 2. 当前总体目标

使用 RA6M5 控制水果输送、摄像头采集、分类判断、舵机分流、定量装盒和翻盖盒压盖。

当前阶段优先完成硬件控制闭环，不追求复杂 AI 模型，先实现可演示流程。

## 3. 当前阶段目标

- 推理板/摄像头板：完成 OV2640 图像采集流程。
- 控制板：完成电机、舵机、光电开关、包装流程的状态机控制。
- 后续：实现两块板之间串口通信，推理板发送分类结果，控制板执行分拣动作。

## 7. 推荐的软件结构

后续整理代码时，可以按功能模块拆分，建议结构如下：

```text
src/
├── camera/
│   ├── camera.c
│   └── camera.h
├── motor/
│   ├── motor.c
│   └── motor.h
├── servo/
│   ├── servo.c
│   └── servo.h
├── sensor/
│   ├── sensor.c
│   └── sensor.h
├── state_machine/
│   ├── system_state.c
│   └── system_state.h
├── protocol/
│   ├── uart_protocol.c
│   └── uart_protocol.h
└── app/
    ├── app_main.c
    └── app_main.h
```

为什么这样划分：摄像头、电机、舵机、传感器、状态机和通信协议分别属于不同功能，分开后便于单独调试，也方便后续定位问题。

## 8. 推荐状态机

建议系统主流程使用以下状态：

```c
typedef enum
{
    SYSTEM_IDLE = 0,
    SYSTEM_FEEDING,
    SYSTEM_WAIT_FRUIT,
    SYSTEM_CAPTURE_IMAGE,
    SYSTEM_CLASSIFY,
    SYSTEM_SORTING,
    SYSTEM_WAIT_BOX,
    SYSTEM_PACKING,
    SYSTEM_CAPPING,
    SYSTEM_OUTPUT,
    SYSTEM_ERROR
} system_state_t;
```

状态含义建议：

| 状态 | 含义 |
| --- | --- |
| `SYSTEM_IDLE` | 系统空闲，等待启动 |
| `SYSTEM_FEEDING` | 输送带运行，水果进入检测区域 |
| `SYSTEM_WAIT_FRUIT` | 等待光电开关检测到水果 |
| `SYSTEM_CAPTURE_IMAGE` | 触发摄像头拍照 |
| `SYSTEM_CLASSIFY` | 根据图像或串口结果判断水果类别 |
| `SYSTEM_SORTING` | 舵机控制分流挡板动作 |
| `SYSTEM_WAIT_BOX` | 等待包装盒到位 |
| `SYSTEM_PACKING` | 定量装盒或等待水果进入盒内 |
| `SYSTEM_CAPPING` | 控制压盖机构完成翻盖盒盖合 |
| `SYSTEM_OUTPUT` | 成品输出 |
| `SYSTEM_ERROR` | 异常处理，例如通信失败、超时或传感器异常 |

## 10. 注意事项

- 不要同时给舵机和主控板直接共用不稳定电源。
- 舵机、电机、传感器和 RA6M5 必须共地。
- L298N 驱动电机时注意外部 12V 电源。
- 摄像头调试应先验证寄存器，再验证 FIFO，再验证完整图像。
- 当前阶段不要过早加入复杂 AI，先让系统流程跑通。
- 串口通信协议建议先保持简单，例如：帧头 + 分类结果 + 校验/结束符。
- 调试摄像头时，建议先固定分辨率和图像格式，避免多个变量同时变化导致问题难定位。
